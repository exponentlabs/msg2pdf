# ADR 0009: Fedora raster profile and system-managed independent verifiers

- Status: Accepted for the initial Fedora 44 ARM64 studio profile
- Date: 9 November 2026
- Scope: Closes B1's local profile qualification and verifier-distribution decision; refines ADRs 0004 and 0008

## Decision

Use `fedora-raster-v1` for the first local studio slice: PDF.js `6.5.438` produces fixed reviewed RGB snapshots at scale 2; marks are rounded outwards to whole pixels and burned black; pdf-lib `1.17.1` creates a new image-only PDF. Source objects are never copied. Limit inputs to 8 pages, 4 million aggregate rendered pixels and 100 MiB. Password-protected, repair-required, unrenderable and over-budget inputs are blocked. Geometry and rendering are fixed to the recorded page boxes, rotation, user units and engine version.

This profile deliberately discards searchable text, OCR, tags, accessibility structure, forms, attachments, scripts, source metadata and digital signatures. These losses must be shown before applying the profile, and the actual final candidate must be reviewed on every page. Review concerns the captured PDF.js appearance, not every component of a native input. Structural redaction and searchable-output regeneration remain outside the initial profile.

Use QPDF `12.3.2` and Poppler `26.01.0` as separate independent PDF implementations. QPDF provides complete object/encoded/decoded-stream inspection. A verifier independent of the assembler permits only the specified page tree, neutral metadata, single RGB image per page and fixed image-painting content. It checks every referenced and unreferenced object, exact decoded mask pixels, exact unchanged pixels against the reviewed snapshot, complete compressed-stream consumption and exact whole-file serialization. The last check rejects hidden gaps, arbitrary comments, obsolete revisions, extra trailers and trailing payloads. Poppler separately parses, extracts text, inventories attachments and renders every saved page. No mandatory checker can be replaced by the removal/rendering implementation.

Source renderers can disagree locally, especially on unembedded fonts. Record independent source-render comparison as diagnostic evidence. The mandatory preservation comparison is exact RGB equality against the immutable, hash-bound snapshot actually reviewed by the user. The snapshot and plan hashes must be bound into candidate evidence; arbitrary renderer-supplied snapshots cannot confer approval. Machine checks establish the chosen profile and masks, while human review determines sensitive content and approves the actual candidate.

Distribute the verifiers through Fedora's signed system packages, separately from the Apache-2.0 application: require `qpdf`, `poppler-utils`, `bubblewrap` and `util-linux`. Do not bundle QPDF, Poppler or their dynamic libraries, download them during document processing, or change the application's licence. Install prerequisites explicitly at machine setup. Check fixed tool paths, supported versions and binary fingerprints before processing and bind them into verification evidence. Missing tools, version changes, failures, timeouts or ambiguous results block the profile; a tool upgrade requires a new qualification record/contract. System packages remain serviced by the distro. Other platforms need native deployment and qualification decisions before enabling the studio there.

Run verifier processes inside bubblewrap with only the required runtime/fonts and scoped input/output files, no host network or unrelated user files. Native tools have 512 MiB address-space, 15-second CPU, 96 MiB file-output and wall-clock/buffer limits. The production service must enforce its own worker/job/cancellation budgets and bind approvals to current evidence; those are B3–B6 implementation responsibilities, not approvals granted by B1.

## Evidence and consequences

The [qualification record](../evidence/b1-qualification-fedora-arm64.json) records 37 passing checks using installed `/usr/bin/qpdf`, packaged Electron and the independent checker worker. Fixtures cover text, rotated/cropped and mixed-size pages at all right-angle rotations, nondefault user units, image-only pages, shared images, zero marks, hidden OCR, metadata, embedded attachments, actions/forms/tags/alternate text, fragmented/clipped text, ligature mappings, vectors, optional layers and genuine incremental history. Negative tests reject hidden objects/streams, scripts, masks, stale revisions, appended payloads, unapplied masks, changed unmarked pixels, password protection, required repairs, missing/timed-out checkers and resource-limit violations.

This selects and qualifies a bounded local profile; it does not certify arbitrary PDFs or enable publication without the case/review/release gates. MuPDF remains an external evaluation only and is not a studio runtime dependency. Its removal-only candidate retained hidden data, and no compatible structural-engine distribution arrangement was selected. Profile changes, PDF.js/pdf-lib upgrades, serialization changes or verifier changes require fresh qualification and approval invalidation.

Licensing/protocol references: [QPDF licence](https://github.com/qpdf/qpdf/blob/main/manual/license.rst), [QPDF complete JSON object representation](https://qpdf.readthedocs.io/en/stable/json.html), [Poppler project](https://poppler.freedesktop.org/). Local packages retain their own licence files and system-package lifecycle. No claim about bundling obligations is needed because these binaries are not redistributed with the app.
